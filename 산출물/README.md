# AI 도서 추천 서비스 (07-pjt)

사용자가 입력한 도서 취향을 바탕으로 책을 추천하고, 표지 이미지를 생성하고, 책 표지를 분석하고, 추천 내용을 음성으로 들려주는 서비스입니다.

화면을 맡는 **Django**와 AI 모델 호출을 맡는 **FastAPI Proxy 서버**로 역할을 나누었습니다.

```
[브라우저] ──▶ [Django :8080] ──▶ [FastAPI Proxy :8081] ──▶ GMS (OpenAI 호환 API)
              폼 검증, 화면, 흐름 제어     Guardrail, 모델 호출, GMS Key 보관
```

- 브라우저는 Django만 호출하고, FastAPI는 Django만 호출합니다.
- GMS Key는 `server/proxy/.env`에만 있으며 Django와 브라우저는 키를 갖지 않습니다.
- Guardrail은 텍스트 추천, 이미지 생성, 이미지 분석 API 안에서 항상 먼저 실행됩니다.

## 실행 방법

Python 3.11과 GMS 키가 필요합니다. 아래 명령은 저장소 최상위 폴더에서 시작합니다. (Windows PowerShell 기준)

**1. 가상환경과 패키지 (한 번만)**

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r server\requirements.txt
```

**2. GMS 키 설정 (한 번만)**

```powershell
Copy-Item server\proxy\.env.example server\proxy\.env
```

`server/proxy/.env`를 열어 `GMS_KEY`에 발급받은 키를 넣습니다. 이미지 생성이 `Model gpt-image-1-mini is not available`로 실패하면 같은 파일의 `GMS_IMAGE_MODEL` 줄 주석을 풀어 주세요. ([이유](#명세와-다르게-구현한-부분))

**3. FastAPI 서버 실행 (터미널 1)**

```powershell
cd server\proxy
uvicorn main:app --port 8081 --reload
```

**4. Django 서버 실행 (터미널 2, 가상환경을 다시 활성화한 뒤)**

```powershell
cd server\web
python manage.py migrate
python manage.py runserver 8080
```

브라우저에서 http://localhost:8080 으로 접속합니다. FastAPI API는 http://localhost:8081/docs 에서 바로 호출해 볼 수 있습니다.

**테스트**

실제 GMS를 호출하지 않으므로 키와 토큰 없이 실행할 수 있습니다.

```powershell
cd server\web;   python manage.py test     # Django 42개
cd server\proxy; python -m unittest        # FastAPI 29개
```

## 구현 기능 설명

### 필수 기능

| 번호 | 요구사항 | 구현 내용 |
|---|---|---|
| F701 | 입력 검증 | `RecommendationForm`(ModelForm)이 빈 값과 300자 초과를 검증합니다. 입력창에도 `maxlength=300`이 적용되어 300자를 넘겨 입력할 수 없습니다. 실패하면 오류 메시지와 함께 같은 화면을 다시 보여줍니다. |
| F702 | 텍스트 추천 생성 | `/chat/completions`가 경량 모델(gpt-5-nano)로 책 제목, 저자, 추천 이유를 생성합니다. |
| F703 | Guardrail 구현 | `/chat/guardrail`이 `response_format`으로 `{"is_appropriate": bool}`만 반환합니다. 폭력, 자해, 혐오, 성인 콘텐츠, 명백한 불법 행위, 타인의 개인정보 요구만 거르고 모호하면 통과시킵니다. 생성 API의 첫 줄에서 실행되어 부적절하면 403을 돌려주고 생성하지 않습니다. 판단 자체가 실패하면 503을 돌려주고 통과시키지 않습니다. |
| F704 | 라우트 결정 | `/decide-route`가 enum으로 제한된 응답을 사용해 `/chat/completions` 또는 `/images/generations`를 고릅니다. |
| F705 | 이미지 생성 API | `/images/generations`가 표지를 생성해 base64로 반환합니다. (`quality: low`, `output_format: jpeg`) |
| F706 | 공통 에러 처리 | 모든 GMS 호출이 `gms_post`를 거칩니다. 200이 아닌 응답, 시간 초과, 연결 실패를 터미널에 기록하고 503으로 통일합니다. Django는 403이면 거절 화면, 그 외 실패면 재시도 안내 화면을 보여줍니다. |
| F707 | 이미지 분석 구현 | 업로드한 표지를 base64 data URI로 보내 제목과 장르를 추정하고 비슷한 책을 추천합니다. Guardrail에는 질문 텍스트만 보내며, 거절된 요청의 사진은 저장하지 않습니다. |
| F708 | API 흐름 제어 | 입력 하나로 Django가 라우트 결정, 기능 실행, 결과 정리를 순서대로 처리합니다. 응답 코드에 따라 결과, 거절, 재시도 안내 화면으로 나뉩니다. |

### 심화 기능

| 번호 | 요구사항 | 구현 내용 |
|---|---|---|
| F709 | 텍스트 응답 점수 계산 | `/chat/score`가 추천이 취향에 맞는 정도를 0~100점과 이유로 평가합니다. 채점이 실패해도 추천 결과는 그대로 보여줍니다. |
| F710 | 모델 등급 라우팅 | 토글을 켜면 gpt-5-nano가 요청을 simple 또는 complex로 분류하고, complex면 gpt-5-mini로 생성합니다. 사용한 모델명을 화면에 표시합니다. |
| F711 | TTS 기능 구현 | `/generate-speech`가 gpt-4o-mini-tts(voice: nova, mp3)로 만든 음성을 base64로 반환하고, Django가 `<audio>`의 data URI로 재생합니다. 추천 결과 화면의 "이 추천 듣기" 버튼을 누르면 추천 내용을 바로 음성으로 들을 수 있습니다. |
| F712 | 이미지 미디어 서빙 | base64 이미지를 `media/images/`에 uuid 파일명으로 저장하고 `/media/...` 주소로 제공합니다. |

### 비기능 요구사항

| 번호 | 요구사항 | 구현 내용 |
|---|---|---|
| NF701 | URL 구성 | `app_name = 'recommend'`를 지정하고 템플릿 링크는 `{% url %}`만 사용합니다. 경로를 직접 쓰면 테스트가 실패합니다. |
| NF702 | API Key 관리 | 키는 `server/proxy/.env`에만 저장하고 `os.getenv`로 읽습니다. `.env`는 `.gitignore`에 등록했으며, 전체 커밋 이력에 실제 키가 없음을 확인했습니다. |
| NF703 | CSRF 보호 | 모든 POST 폼에 `{% csrf_token %}`을 넣었습니다. 토큰이 없는 POST는 403으로 거절됩니다. |
| NF704 | 호출 시간 제한 | FastAPI → GMS는 120초, Django → FastAPI는 180초입니다. |

### UI

Apple 홈페이지의 디자인 문법을 참고했습니다. 44px 반투명 내비게이션, 블랙과 라이트 그레이가 번갈아 나오는 풀블리드 섹션, 큰 제목, 알약 모양 버튼, 12px 간격의 2열 타일을 사용했습니다. Apple의 로고와 이미지는 쓰지 않았고, 홈 화면의 책 그림은 CSS로 직접 그렸습니다. 화면 폭 390px까지 가로 스크롤 없이 동작합니다.

### 검증 범위

- **실제 GMS 호출로 확인**: F702~F712의 모든 화면. Guardrail 9개 사례(프롬프트 인젝션 시도, 추리 소설처럼 어두운 주제의 정상 요청 포함)와 라우트 6개 사례가 모두 기대대로 판단되었습니다. GitLab에서 새로 클론한 코드로 설치, 테스트, 주요 화면 동작까지 다시 확인했습니다.
- **실제로 한 번 발생해 확인**: GMS 응답이 멈췄을 때 120초 후 FastAPI가 503을 돌려주고 Django가 안내 화면을 보여주는 흐름. (아래 TTS 문제를 조사하던 중 발생)
- **mock 테스트로만 확인**: Django → FastAPI 180초 시간 초과.
- **확인하지 못함**: `gpt-image-1-mini`로 이미지 생성. GMS가 모델을 거부해 실제 이미지는 `gpt-image-2`로 생성했습니다.

### 알려진 한계

- LLM이 실제와 다른 도서 정보를 답할 수 있습니다. 예를 들어 F710 캡처의 "보통의 존재 — 은유"는 저자가 틀렸습니다(실제 저자는 이석원). 프롬프트로 "실제로 출간된 책만 추천"을 요구해도 막지 못해서, 화면 하단에 이 점을 안내했습니다. 도서 API로 검증하면 해결할 수 있지만 이번 범위에는 넣지 않았습니다.
- 아주 긴 글은 TTS가 끝까지 읽지 않을 수 있습니다. 측정해 보니 906자는 93초였는데 1,812자는 80초였습니다. 일반적인 추천 답변 길이(446자, 57초)에서는 문제가 없었습니다.

## 명세와 다르게 구현한 부분

필수 기능의 동작은 명세대로이며, 아래는 실행 중 발견한 문제를 해결하거나 사용성을 높이려고 바꾼 부분입니다.

| 항목 | 명세 또는 스켈레톤 | 이 프로젝트 | 이유 |
|---|---|---|---|
| 이미지 모델 | `gpt-image-1-mini` | 코드 기본값은 그대로이고, `.env`의 `GMS_IMAGE_MODEL`로 바꿀 수 있음. 캡처는 `gpt-image-2`로 실행 | 2026-11-06 기준 GMS가 `gpt-image-1-mini`를 거부함 (`Model gpt-image-1-mini is not available`) |
| TTS 전송 방식 | 오디오 바이트를 그대로 받음 | `stream_format: "sse"`로 받아 조각을 이어 붙임. 결과는 명세대로 mp3의 base64 | GMS가 오디오를 그대로 보낼 때 약 130KB(한글 50자 안팎)에서 전송을 멈춰, 추천문처럼 긴 글은 120초 후 실패함. curl로도 같은 지점에서 멈춤 |
| Proxy 서버 미실행 시 | Django 오류 화면(ConnectionError) | "Proxy 서버에 연결하지 못했습니다" 안내 화면 | F706의 "적절한 안내 화면" 취지. 시간 초과에도 같은 처리가 필요함 |
| 첫 화면 | `/`가 입력 검증 | `/`는 서비스 소개, 입력 검증은 `/validate/` | Apple 스타일 홈 화면 추가 |
| 추론 강도 | 기본값 | 판단 호출 `minimal`, 생성 호출 `low` | 토큰과 대기 시간 절감 (아래 측정값) |
| Proxy 주소 | `localhost` | `127.0.0.1` | Windows에서 `localhost`는 호출마다 약 2초 지연 (2.06초 → 0.02초) |
| `requirements.txt` | 한글 주석 포함 | ASCII만 사용 | 한국어 Windows에서 pip가 cp949로 읽어 `UnicodeDecodeError` 발생 |
| 이미지 분석 형식 | data URI를 `image/png`로 고정 | 파일 내용으로 확인한 실제 형식 전달, PNG와 JPG만 허용 | JPG를 PNG로 표시하지 않기 위함 |
| 이미지 분석 저장 시점 | 호출 전 저장 | 성공한 뒤에 저장 | 거절된 요청의 사진을 남기지 않기 위함 |

`reasoning_effort`를 바꾸며 측정한 값입니다. (gpt-5-nano, 각 1회 측정이라 참고용입니다)

## 학습 내용

- **역할 분리와 Proxy 서버**: Django는 화면과 흐름만, FastAPI는 모델 호출과 키 보관만 맡기면 키가 노출될 경로 자체가 줄어든다는 것을 배웠습니다. 모델을 바꾸거나 오류 처리를 고칠 때도 FastAPI 한 곳만 수정하면 됩니다.
- **LLM 응답 형식 제한**: `response_format`의 JSON 스키마를 쓰면 문자열 파싱 없이 bool, enum, 정수를 받을 수 있습니다. 다만 `strict` 스키마가 값의 범위까지 보장하지는 않아 점수를 0~100으로 다시 맞췄습니다.
- **Guardrail 설계**: 기준을 엄격하게 쓰면 "연쇄살인범이 나오는 추리 소설"같은 정상 요청까지 막힙니다. 명백한 경우만 거르고 모호하면 통과시키되, 판단이 실패하면 통과시키지 않는 것이 핵심이었습니다.
- **멀티모달 데이터 전달**: 이미지와 음성을 base64 문자열로 주고받는 방법과, 작고 일회성인 결과는 data URI로, 크고 다시 쓰는 결과는 media 파일로 제공하는 기준을 익혔습니다.
- **오류 처리와 시간 제한**: 응답 코드만 확인해서는 부족하고 시간 초과와 연결 실패는 예외로 잡아야 503을 돌려줄 수 있습니다. 바깥쪽 호출의 제한을 더 길게 잡아야 안쪽에서 보낸 오류 응답을 받을 수 있다는 것도 배웠습니다.
- **문제를 좁혀 가는 방법**: TTS가 긴 글에서만 멈췄을 때 입력 길이, 줄바꿈, 파일 형식, HTTP 클라이언트를 하나씩 바꿔 비교했습니다. curl에서도 정확히 같은 바이트에서 멈추는 것을 보고 내 코드가 아니라 전송 구간의 문제라고 판단했고, SSE 방식이라는 해결책을 찾았습니다.
- **Django 폼과 보안**: ModelForm의 `max_length`가 서버 검증과 입력창의 `maxlength`를 함께 만들어 주는 것, `ImageField`가 파일 내용으로 형식을 확인해 주는 것, CSRF 토큰이 없는 POST가 막히는 것을 확인했습니다.

## 느낀 점

가장 크게 느낀 점은 mock 테스트가 통과해도 실제 호출은 다를 수 있다는 것입니다. Guardrail 테스트는 모두 통과했는데 실제 호출에서는 500이 났고, 명세대로 FastAPI 터미널 로그를 먼저 보니 원인을 바로 찾을 수 있었습니다. 이미지 모델도 코드만 봐서는 알 수 없었고, 실제로 호출한 뒤에야 GMS가 해당 모델을 거부한다는 것을 알았습니다.

TTS가 특히 기억에 남습니다. 명세의 예시처럼 짧은 문장은 2초 만에 재생되어 완성된 줄 알았는데, 마지막에 새로 클론해서 추천문을 듣는 흐름까지 확인해 보니 120초를 기다린 뒤 실패했습니다. 예시만 확인하고 끝냈다면 정작 추천을 듣는 기능은 동작하지 않는 채로 제출할 뻔했습니다. 실제 사용 흐름대로 끝까지 눌러 봐야 한다는 것을 배웠습니다.

토큰 비용을 숫자로 재 본 것도 인상적이었습니다. 불리언 하나를 답하는 데 수백 토큰을 쓰는 것을 보고 옵션 하나로 토큰을 크게 줄일 수 있었습니다. 앞으로 LLM을 사용할 때는 기능이 동작하는지뿐 아니라 얼마나 비싸고 느린지도 함께 측정해야겠다고 생각했습니다.

LLM의 답을 그대로 믿으면 안 된다는 것도 다시 확인했습니다. 프롬프트에 실제 출간된 책만 추천하라고 적어도 저자가 틀린 답이 나왔습니다. 서비스로 만들려면 프롬프트만으로 해결하려 하지 말고 도서 API 같은 외부 데이터로 검증해야 한다고 느꼈습니다.
